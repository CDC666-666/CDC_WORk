# 展示站与私人工作台部署说明

## 状态与域名边界

PR #12、#13、#14 已合并 main。旧文档中的“Draft”“尚未合并”“仅隧道”描述属于历史阶段，不代表当前 PR 状态。本轮只清理公开资料，未连接服务器；当前生产镜像、配置和数据库状态须在另行授权的部署任务中核实。

`cdc666.cn` 用于获准公开的作品集，`work.cdc666.cn` 用于登录后的私人工作台。公开域名的私有路径被拒绝；工作台域名阻止作品集媒体和公开访问统计路径。具体白名单见 `ops/Caddyfile.production`。Web/数据库保持回环监听，由反向代理提供 HTTPS。

公开媒体、联系方式与作品集模型经过授权发布，不读取私人 Workspace。公开统计只返回聚合，禁止输出个人工作台内容和认证信息。

## 版本与配置

部署时分别记录源码 checkout、Web 镜像 revision/digest 和数据库迁移版本，不能从服务器 checkout 推断实际 Web 镜像。具体服务器清单、镜像切换记录和私人数据核对结果留在受限运行目录。

本地与生产使用独立 OAuth App。生产回调为 `https://work.cdc666.cn/api/auth/callback/github`；受限环境配置包括 `DATABASE_URL`、`NEXTAUTH_URL`、`NEXTAUTH_SECRET`、`GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`ALLOWED_GITHUB_USER_ID`，以及公开统计密钥、正式上线时间和已核准备案字段。秘密值不能进入 Git 或构建日志。

备案及联系字段只发布明确获准的值；未配置字段保持隐藏。正式上线时间是公开统计口径，不应替换为构建时间。

## 后续发布流程

以下步骤只供独立部署任务使用，本次文档清理不执行。

1. 核对目标分支与当前 Web 镜像的差异，保留已公开的媒体和配置，不直接用旧 checkout 覆盖较新运行版本。
2. 保存受限的配置副本、旧镜像和 Compose override。先备份，再验证归档，并在全新隔离库做恢复比较；原始结果不公开。
3. 确认目标数据库，审查并应用所需迁移。优先使用可回退的加法迁移，禁止重置生产库或替换数据卷。
4. 构建标记完整提交的镜像，检查健康状态，再只切换 Web。数据库迁移兼容性单独判断。
5. 对实际 HTTPS 域名验证公开路径、媒体、桌面/窄屏布局，及匿名私有 API 401；真实授权登录、刷新和退出需单独验收。公开 QA 流量避免污染统计。
6. 记录检查类别及结论；私人业务数据、指纹、截图、临时记录标识和备份清单不写入公开文档。

## 回退与恢复

Web 回退使用事先保存的镜像与 Compose override，仅重建 Web 服务，保留原数据库卷；配置回退后验证 Caddy 与访问边界。迁移后能否回退旧 Web 必须预先核实，不能用恢复旧数据库覆盖新增业务数据。

需要数据恢复时走独立事故流程，在隔离库确认归档、时点及数据差异，再决定恢复策略。[备份操作](server-backup-operations.md) 与 [本机恢复步骤](database-backup-restore.md) 提供技术约束。

## 公开记录限制

源码 PR 合并不等于重新部署；服务健康不等于真实 OAuth、业务数据正确性或手机布局通过。自动异地备份是否启用、最新归档是否完成实际恢复均须单独核实，不沿用旧报告宣布当前状态。
