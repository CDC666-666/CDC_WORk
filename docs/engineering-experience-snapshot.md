# 单案例快照的历史设计与兼容入口

早期单案例实现由 PR #8 引入，后由 PR #9 扩展为多项目快照，并通过 PR #10 进入 main。当前 `snapshot:experience` 与 `snapshot:experiences` 调用同一脚本；不要把旧设计的单案例选择范围当作当前行为。

当前命令、输出位置及失败语义以 [多项目快照说明](engineering-experience-multi-snapshot.md) 为准。此处不保留私人案例的标题、ID、状态、时间或验收指纹。

## 保留的技术经验

`Knowledge.updatedAt` 是 `timestamp without time zone` 列。把带时区的 JS Date 直接赋给无时区列，可能受 PostgreSQL 会话时区转换影响；应用读回时又按 UTC 解释，造成索引列与 payload 的 UTC 字段不同。

后续原生实体和浏览器迁移写入显式使用 UTC 墙上时间。既有数据不因快照生成而改写；格式同时保留数据库原始时间、生成时间、最近成功核对时间，并提示时间口径差异。

合成示例：在 `Asia/Shanghai` 会话中创建一条临时测试记录，核对数据库列与 payload 的 UTC 值接近，再测试编辑和迁移。该示例不复用私人记录或真实时间戳。

## 检索边界

状态文件、索引和实体正文都属于私人资料，只能在受限环境读取。失败后保留的快照不能被描述为当前数据库状态；生成快照也不会改变记录的证据等级。

凭据形态过滤只是一层保护，不能据此公开业务记录。快照与原来源不计为两份证据；独立检索验收报告只记录流程和适用限制，不公开检索到的记录。
