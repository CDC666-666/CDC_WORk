# 公开源码与私人运行数据

## 可以公开的内容

源码、接口和字段定义、通用操作说明、明确标注的合成测试数据，以及获准发布的作品集资料、项目媒体和联系方式。账号准入机制及已有来源常量属于程序配置或兼容标识，不等于发布对应数据库记录；此次不修改这些机制。

## 不得公开的内容

私人工作台的记录正文、标题、标签、数量、状态、精确时间、实体 ID、来源摘要、内容指纹、账单和学习记录；还包括数据库归档/导出、备份清单、认证数据、原始聊天、浏览器配置及截图。PR 描述、评论、Actions 输出和附件适用相同边界。

需要说明格式时使用全新合成值，例如 `synthetic-record-a` 和“合成示例：材料试验”；不要把真实记录替换标题后继续使用其余字段。固定源码兼容标识不得被当作实际记录存在的证据。

## 提交前检查

1. 用 `git status --short`、`git diff --cached --name-only` 检查提交范围；`.gitignore` 不会移除已经被跟踪的文件。
2. 用 `git check-ignore --no-index <私人文件路径>` 验证忽略规则。尤其注意快照可能生成到代码仓库的父目录，那个目录所属仓库也要有独立忽略规则。
3. 检查文档、测试、截图与 PR 文本，不能从数据库或本地快照复制验收结果。调试输出和备份工具的控制台内容也须留在私人环境。
4. Docker 构建目录同样排除私人文件；Git 忽略不能替代 `.dockerignore`。
5. 发现已跟踪的私人数据时先阻止继续发布，单独核对历史范围；不要通过删除网站数据库来清理 GitHub。
