# Dependency audit: 2026-10-11

Baseline `origin/main@2eb70879cc47e984839f59cf694aa3605e597908` was audited using the npm registry from an isolated Node 22.14.0 container on the server. The local Windows audit endpoint returned `ECONNRESET`; the offline cache's zero finding was not treated as evidence. The baseline report contains **19 affected package entries: 15 high, 4 moderate, 0 critical**. Entries include transitive packages and shared advisory chains; they are not 19 independent exploit paths. The original Dockerfile copied all development dependencies into the runtime image.

The 15 **high** entries were `@next/eslint-plugin-next`, `@prisma/config`, `brace-expansion`, `braces`, `browserslist`, `chokidar`, `deepmerge-ts`, `eslint-config-next`, `fast-glob`, `js-yaml`, `micromatch`, `prisma`, `sharp`, `source-map-js`, and `tailwindcss`. The 4 **moderate** entries were `baseline-browser-mapping`, `next`, `postcss-nested`, and `postcss-selector-parser`. Their runtime exposure differs: Next.js and Sharp can affect served requests when the advisory's conditions are met; Prisma CLI runs at startup and during migrations; the remaining CSS, browser-data and ESLint/Tailwind chains primarily process build or developer input. The table below records the patch or remaining work for each group.

The candidate lockfile's full audit is **7 high, 0 moderate**; `npm audit --omit=dev` is **0** after moving the startup migration CLI to production dependencies. The final Docker stage runs `npm prune --omit=dev`. On 2026-10-11, the built candidate runtime image itself returned zero production findings from `npm audit --omit=dev`; Tailwind was absent and Prisma CLI, Prisma Client and Next.js were present. In an isolated build-stage image, lint, typecheck, 47 unit tests, 17 database tests after six migrations, and build passed. The `deepmerge-ts` and selector-parser transitive overrides cross major versions; these checks cover current application paths, not every future tool-chain path.

The candidate Web image `sha256:31320a567035ddf48525068cad5e70441149ff6cc4b26bf605c7e02a6e3a54a0` was then deployed through a server-only Compose override, while the server Git checkout remained clean at `main@2eb70879cc47e984839f59cf694aa3605e597908`. This image corresponds to that commit plus the **uncommitted** dependency and Dockerfile changes on `codex/launch-prep`; it is not a released Git revision. Both containers were healthy. A user-completed GitHub login over the SSH tunnel, private API 200, temporary engineering experience create/edit/refresh/search/delete, original case read, and logout returning private API 401 passed. The temporary row was removed; the original experience fields and payload digest matched the pre-deployment baseline. Public-domain access and production OAuth remain untested.
